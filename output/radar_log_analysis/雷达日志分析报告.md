# 专家雷达日志数据分析

分析对象：`20260613_201032.dat(1).txt`、`20260613_224616.dat(1).txt`、`20260614_234131.dat(1).txt`。

本报告只分析这三份实际文件。原始文件未修改；不纠正鸟和无人机的识别结果，也不把设备输出视为人工真值。所有结论来自日志本身与字段间的一致性核查，不依赖外部雷达规格。

## 1. 先看结论

这是一批**雷达处理后的目标航迹日志**。一行代表某个航迹在某个时刻的一条状态记录，不是一架无人机，也不是一段完整飞行。文件不包含原始回波、I/Q、距离多普勒图或微多普勒谱。

最有价值的是：**目标在什么时候、什么位置出现，怎样运动，持续跟踪了多久，以及何时失去跟踪**。适合先做真实航迹回放、位置与运动特征提取、短时轨迹预测原型，以及跟踪质量分析。

最需要注意的是：**三份文件的“目标类型”全部为“未知”，置信度全部为 1.00**。虽然专家提到鸟与无人机容易混淆，这三个导出文件本身并没有鸟/无人机标签，也没有有区分度的分类置信度。

第三份文件：雷达 ID 1 有 541 条记录、65 个航迹键；雷达 ID 2 有 529 条记录、65 个航迹键。若忽略雷达 ID，只剩 125 个不同航迹编号，其中 5 个编号在两个雷达 ID 中都出现过。因此不宜只按“航迹编号”合并。ID 1 和 ID 2 的观测时间重叠，但日志不足以确认它们是独立站点、设备通道还是其他配置。

829.49 秒是三个片段覆盖时长之和，不是连续观测时长，更不是所有目标的累计飞行时长。

## 3. 18 个字段分别是什么、有什么用

原文件是制表符分隔文本，可按 GBK 解码。没有字段单位和厂家协议，以下把日志中可以直接观察到的事实与推断分开说明。

| 字段 | 含义与本次观察 | 使用价值与限制 |
|---|---|---|
| 时间 | 带毫秒的记录时间；1,803 条均能解析 | 轨迹排序、更新间隔、回放的首选时间列；需确认时区和时间来源 |
| 搜索方位 | 雷达搜索指向，数值与目标方位并不相同 | 研究扫描覆盖和目标被照射的时机；不要当成目标运动航向 |
| 扫描周期 | 整数计数；例如第一份从 370 到 447 | 更像扫描轮次编号，不是“周期为 370 秒”；可辅助检查漏更新 |
| 目标有效标志 | 取值 0/1；0 有 1,617 条，1 有 186 条 | 与航迹生命周期强相关，详见质量问题；协议确认前保留原值 |
| 航迹编号 | 雷达侧的航迹标识 | 串联同一航迹，需联合来源文件和雷达 ID 使用 |
| 幅度 | 48.43—96.59 | 可研究回波强弱随距离和时间的变化；单位、校准不明，不能直接当作 RCS、目标尺寸或可靠性分数 |
| 目标速度 | -29.60—20.21，有正负号 | 与距离变化呈负相关，更像带方向符号的径向速度；不能直接当完整飞行速度 |

| 目标方位 | 17.67°—219.60°，角度单位为推断 | 目标水平方向；与俯仰、斜距可构建局部坐标；零点及旋转方向待协议确认 |

| 置信度 | 所有记录固定为 1.00 | 本批数据中没有区分作用，不能解释为识别准确率 100% |
| 目标类型 | 所有记录都是“未知” | 本批数据没有鸟/无人机监督标签 |
| UTC_TIME | 前两份可解析；第三份全部非法 | 第三份不能用这一列做时间同步；前两份与“时间”列也有亚秒级差异 |

| 纬度 | 22.3461534106—22.3827272183 | 同上；很多小数位不等于同等测量精度 |
| 高度 | 8.90—464.22 | 几乎等于“目标高度”加每文件固定偏移；属于另一参考面的高度表达，基准待确认 |

位置量按米、角度按度、速度按米/秒进行内部一致性核查时能得到合理关系，但这仍不能替代厂家字段说明。

## 5. 已确认的问题与需要谨慎解释的规律

### 5.1 第三份 UTC_TIME 全列损坏

1,070 条记录均为 `-17776/80/80_80:-2:0.-160`。本地“时间”列则全部可解析且按文件行序不倒退，仍可用于片段内相对时间分析。

前两份“时间减 UTC_TIME”约为 8 小时，但减去 8 小时后仍分别有 -0.748—0.447 秒、-0.627—0.385 秒的差异。两列可能采用不同时间来源或写入机制，不能假设毫秒严格对齐。若将来按“时间减 8 小时”生成推定 UTC，必须明确标注为推定值，而不能覆盖原始 UTC_TIME。

### 5.2 有效标志 1 全部是航迹末行

**186 条标志 1 全部出现在各航迹键最后一条记录，每个相关航迹键恰好一条；剩余 13 个航迹键没有标志 1。**

这一事实支持“航迹终止、失效、删除消息或某种末次状态”的解释；具体是哪一种，要查厂家协议。不能仅凭“有效标志”这个名称认定 1 是高质量实测点。没有标志 1 的航迹也可能只是被文件结束截断，不能直接认定为一直稳定跟踪。

### 5.3 日志包含疑似预测/外推状态，且不限于标志 1

例如第一份航迹 120（雷达 ID 0，原始第 5、14、20、26 行）：

| 时间 | 标志 | 距离 | 速度 | 俯仰 | 目标高度 | 幅度 |
|---|---:|---:|---:|---:|---:|---:|
| 20:10:34.500 | 0 | 900.00 | -7.84 | 1.82 | 28.54 | 51.25 |
| 20:10:36.443 | 0 | 915.23 | -7.84 | 1.28 | 28.54 | 51.25 |
| 20:10:38.383 | 0 | 930.46 | -7.84 | 0.73 | 28.54 | 51.25 |
| 20:10:40.330 | 1 | 945.69 | -7.84 | 0.19 | 28.54 | 51.25 |

距离按近似固定步长增加，而速度、幅度、高度原样保持。这符合“跟踪器外推或状态保持”的表现，也可能涉及字段更新机制；不能当作原始测量来保证。标志 0 也出现这一现象，所以“删去所有 1”仍不足以得到纯实测点。

### 5.4 速度是重要信息，但不能直接当飞行总速度

以同航迹相邻距离差除时间差构造距离变化率，三份文件中它与“目标速度”的相关系数约为 -0.618、-0.770、-0.599。整体上“距离增大对应负速度”，与朝向雷达为正的径向速度解释相符，但不是每条记录都严格符合。

如果目标沿雷达等距圆方向运动，它可能横向运动很快，而径向速度接近零。因此不能用 `abs(目标速度)` 直接判断悬停、完整速度或真实加速度。完整速度应在统一坐标下从多时刻位置估计，并处理噪声、时间不规则和预测点；更细的加速度、转弯率会进一步放大误差。

### 5.5 两个高度字段高度相关，但都不能直接当离地高度

`高度 - 目标高度` 在每个文件内几乎恒定：第一份为 19.73—19.74，第二份为 19.34—19.35，第三份为 18.80—18.81。它们很可能是相同目标高度换了参考面，不能当成两路独立传感器证据。

`目标高度` 与 `目标距离 × sin(目标俯仰)` 的绝对差中位数仅约 0.018、0.019、0.019 米；但全样本最大差分别达到 25.404、14.443、21.938 米。标志 1 的误差中位数约 1.54—1.82 米，明显高于标志 0 的约 0.017 米，提示部分字段更新或外推不一致。导出中已保留残差，超过 1 米仅作为本次探索标记，不是厂家质量阈值。

共有 104 条“目标高度”为负，不能据此认定目标在地下。若其参考面为雷达，低于雷达的目标可以为负；是否为离地高度需要地形及高度基准信息。

### 5.6 经纬度很可能是雷达极坐标的另一种表达

按“水平距离 = 斜距 × cos(俯仰)”并按常见北向零度方位约定换算，逐文件拟合坐标原点，经纬度与极坐标转换的平面残差中位数约 0.54、0.35、0.96 米。若直接把斜距当水平距离，残差中位数更大，约 2.79、2.44、1.42 米。

这支持米制斜距和角度字段的解释，也说明经纬度与距离/角度可能来自同一套位置估计。拟合一致性不等于真实测量精度；第三份的转换残差最大约 13.47 米。不要把经纬度与极坐标当成彼此独立的定位真值，也不要把拟合原点当成测绘站址。

### 5.7 文本结构完整不代表测量已验证

三份文件没有发现空单元格、整行重复、列数错误、数值字段解析失败或“时间”列解析失败。质量问题主要在字段语义、时间同步、航迹生命周期及状态估计一致性方面。

## 6. 对当前项目真正有用的方向

| 方向 | 现有数据能提供什么 | 当前边界 |
|---|---|---|
| 真实雷达航迹回放 | 时间、位置、高度、编号、来源 | 可以直接做；先按来源划分航迹，并保留质量标记 |
| 跟踪质量分析 | 更新间隔、持续时间、断点、末行标志、字段保持现象 | 很有价值；无法仅凭日志计算真实探测率、误检率或定位误差 |
| 轨迹特征提取 | 平滑后水平/垂直速度、接近/远离、转向、位置波动 | 可以做；先确认单位、参考系与实测/预测状态 |
| 短时轨迹预测原型 | 用历史位置预测后续位置 | 可先比较匀速、Kalman 等基线；日志中的未来点也可能是设备预测，不能当独立真实轨迹验证 |
| 空域活动可视化 | 观测到的目标点、航迹及高度随时间变化 | 可做片段内展示；没有覆盖区域和无目标扫描日志，不能等同于真实目标密度或全天活动规律 |
| 与我方无人机做接近风险分析 | 外部运动目标的位置与估计速度 | 还要有同时间、同坐标基准的我方位置/速度，才能计算目标间距离及最近接近 |
| 鸟/无人机识别训练 | 位置与运动、幅度等候选特征 | 缺少可信类别标签，不能据此训练或报告有监督识别准确率 |
| 事故概率或地面伤害风险 | 一部分位置和运动观测 | 缺少事故结果、目标身份/质量及必要环境输入，不能直接当事故训练数据 |

文件夹叫“气象台”，但这 18 列里没有风速、风向、气压、降水等气象观测。它记录的是被探测目标，不是目标飞控遥测；没有目标自身的机身姿态、控制指令、电池、避障传感器或任务意图。

项目的 `intentra_x/air_risk_features.py` 中，现有 12 维输入包含自身高度、三轴速度、总速度、roll、pitch、风速/风向及机载障碍距离/标志。这份雷达日志无法提供其中多数变量。“目标俯仰”不能替代机身 pitch，“目标距离”也不能替代机载障碍距离。更合理的定位是作为**外部空域感知数据源**，再与我方飞行遥测配合；不宜直接补零接入现有模型并解释其输出。

## 7. 如果用于序列研究，实际有多少样本

仅作样本规模估算：按航迹键分组，遇到相邻间隔超过 5 秒就另起一段，采用 20 点输入窗口、步长 1，不跨段。

- 保留所有原始状态：14 个片段至少有 20 点，可以生成 211 个 20 点输入窗口。
- 若探索性排除标志 1 的末行：13 个片段至少有 20 点，可以生成 197 个输入窗口。这不是已经完成质量筛选的数据集。
- 20 点在典型间隔下跨度约为 `19 × 1.943 = 36.9 秒`。
- 这些只计算输入窗口；若还需要后续若干点作为预测标签，可用窗口会减少。
- 高度重叠的窗口不等于独立样本。训练/验证应至少按航迹分组，并优先检验按采集片段或日期隔离的结果，避免同一轨迹的相邻窗口落入不同集合。未来如发现跨 ID 的同一目标，还需一起分组。

这批数据更适合做解析验证、真实数据演示和小规模方法比较。仅有三个短片段，不足以支持复杂模型的泛化结论。

## 8. 后续最值得向专家索取的信息

1. **字段协议与状态码表**：单位、正负号、扫描编号定义，尤其是有效标志 0/1、航迹结束消息，以及实测点与预测点如何区分。
2. **时间和空间基准**：两列时间分别来自哪里、第三份 UTC 损坏原因、经纬度坐标系、两个高度参考面、雷达 ID 的实际含义。
3. **同步真值**：若有无人机配套飞控/GNSS 轨迹、同步视频或人工核验时间段，可用于验证位置、运动及类别，而不依赖雷达自身输出。
4. **更长且含覆盖信息的日志**：需要完整观测时段、扫描覆盖/配置、未输出目标时的扫描状态，才能讨论检出率、漏检或长期活动规律。
5. **按研究目的补数据**：若以后专门做鸟/无人机识别，再索取对应人工标签及可获得的回波或多普勒特征；这不影响现在先做航迹与质量分析。
